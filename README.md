## How I think about software and product adoption

I've spent much of my career working with analytical software that requires both technical precision and substantial domain knowledge.

That experience shapes a few principles behind my work:

1. **Good APIs are part of the product experience.** Developers should not have to understand every implementation detail to use a tool effectively.
2. **Documentation is part of the product, not an afterthought.** Clear examples and guidance reduce friction and make technical capabilities accessible.
3. **Testing builds trust.** Especially in analytical software, correctness, reproducibility, and understandable outputs matter.
4. **AI should improve the development process without replacing engineering judgment.** Generated code still needs thoughtful design, testing, and review.
5. **Successful software is software people can adopt.** The full experience matters, from installation and onboarding to everyday usage and ongoing support.
